# MBA 설계 — 구조 · IR/DSL 명세 · 검증 계획

> **설계 초안 — 선행조사(docs/선행조사.md, 병렬 작성 중)를 본 뒤 확정.**
> 이 문서는 선행조사를 읽지 않고 썼다. 아래에서 선행연구(Remote Agent, Livingstone, 포섭 구조 등)를
> 부르는 자리는 모두 **[미확인 — 선행조사에서 대조]** 로 표시했다. 확인 전에는 인용이 아니라 이름일 뿐이다.
> 코드는 아직 없다. 이 문서의 모든 수치는 **정의**(상한·예산 기본값)이지 **측정**이 아니다.

## 0. 한 줄 요약과 이 문서가 고정하려는 것

**LLM 은 컴파일러다.** 자연어 명령을 한 번 IR 로 옮기고 나면, 매 주기 도는 코어(상태 추정 · 믿음 갱신 ·
진단 · 정책 조회 · 중재 · 안전 · 행동 · 기록)는 LLM 을 **한 번도** 부르지 않는다.

이 문서가 고정하려는 것은 세 가지다.

1. **토큰 경계** — 어느 부품이 LLM 을 부를 수 있는가(답: [1] 하나와, 코어 밖의 임무 재구성 하나). 그리고
   그것을 **기계로** 붙드는 시험.
2. **IR 과 DSL** — 기호표 · 임무 레코드 · 모형 조각 · 정책 표 · 중재 순서 · 안전층을 무엇으로 적는가.
3. **주장이 무엇이고 무엇이 그것을 깨는가** — "토큰을 아낀다" 는 주장을 재려면 무엇과 비교해야 하고,
   어떤 결과가 나오면 주장을 접어야 하는가.

## 1. 부품 [1]–[8] 과 인터페이스

### 1.1 흐름

```
   (자연어)                                     ┌──────────── 코어: 토큰 0 ────────────────────────────┐
  "연기 속에서      ┌─────────────┐  IR(동결)    │                                                       │
   파란 물체를  ──▶ │[1] 의도 파서 │ ──────────▶ │ [2] 기호표 ─▶ [3] 사건/상태 기계 ─▶ [6] 국소 정책·중재 │
   찾아"            │ (LLM 가능)   │  MISSION 01 │       ▲              │    ▲               │           │
                    └─────────────┘              │       │              ▼    │               ▼           │
                          ▲                      │       │   [4] 믿음 캐시 ◀─▶ [5] 고장 모형     안전층   │
                          │ 임무 재구성           │       │   (상태 해시)      (국소 진단)        │       │
                          │ (예산 있음,           │       │                                      ▼       │
                          │  코어 밖)             │   [8] 관측 ◀──────── 환경 ◀──────────── [7] 행동   │
                          │                      │                                                       │
                          └── 임무 관리자 ◀──── UNKNOWN 이 안전 대체로도 안 풀리고, 임무가 불가능할 때만 ──┘
```

### 1.2 부품별 입출력 (모두 기호 ID)

ID 접두: `S##` 상태 술어(비트) · `E##` 사건 · `A##` 행동 · `F##` 고장 모드 · `C##` 부품 · `B##` 행동층(behavior) ·
`R##` 규칙 · `M##` 임무 · `G##` 모형 조각. 정의는 §2.1.

| # | 부품 | 입력 | 출력 | LLM | 주기 |
|---|---|---|---|---|---|
| [1] | 의도 파서 | 자연어 문자열 · 기호표(어휘) | `MISSION` 레코드(§2.2) — 기호 ID 만 | **가능** (결정적 파서 먼저, 실패 시만) | 임무당 1회 |
| [2] | 기호표 · 컴파일러 | `.mba` 소스 + `MISSION` | 동결 IR: 비트 배정 · 정책 표 · 의존 원뿔 · 관련 색인 | 금지 | 임무 시작 1회 |
| [3] | 사건/상태 기계 | `S`-비트 벡터(이전) · 관측 술어 | `E` 사건 집합(상승/하강 에지) · 새 `S` 벡터 | 금지 | 매 주기 |
| [4] | 믿음 캐시 | (`MISSION`, 모형 버전, 원뿔 안 `S` 비트) 해시 | 캐시된 진단 결과 · 정책 결정 또는 miss | 금지 | 매 주기 |
| [5] | 고장 모형 · 국소 진단 | 사건 `E##` · 그 부품의 의존 원뿔 · 원뿔 안 관측 | 부품 모드 추정 `C## ∈ {nominal, F##…, UNKNOWN}` · 판별 행동 제안 `A##` | 금지 | 사건이 있을 때만 |
| [6] | 국소 정책 · 중재 | `S` 벡터 · `E` 집합 · 모드 추정 | 행동층마다 후보 `A##` → 우선순위로 승자 1개 → 안전층 허가/대체 | 금지 | 매 주기 |
| [7] | 행동 | `A##` + 인자 | 플랫폼 명령 · 실행 결과(Ok/Fault) | 금지 | 매 주기 |
| [8] | 관측 | 플랫폼 원자료 | 관측 술어(임계값 비교) → `S` 비트 후보, 신선도 | 금지 | 매 주기 |

> 표의 "임무 재구성" 은 부품이 아니라 **임무 관리자** 의 동작이다. 코어가 `SAFE_HOLD` 에 들어가 멈춘 뒤에만,
> 코어 **바깥** 에서 [1] 을 다시 부른다(§4).

### 1.3 RAG 를 "모형 조각 검색" 으로

자유 문서를 검색하지 않는다. 컴파일러([2])가 미리 **역색인** 을 만든다: 각 `S` 비트 → 그 비트를 전제로 쓰는
모형 조각 `G##` 목록.

```
relevance[S_SMOKE_HIGH] = {G03 카메라 열화 모형, G05 레이더 가용 모형}
relevance[S_CAM_LOW]    = {G03, G07 탐색 전이 규칙}
활성 조각 = ∪ relevance[s]  (s 는 이번 주기에 켜진 비트)
```

조회 비용은 켜진 비트 수 × 색인 길이 — 둘 다 컴파일 때 상한이 정해진다. 임베딩 · 유사도 검색은 없다.
**잃는 것:** 모형에 없는 상황은 검색으로도 안 나온다. 그것은 UNKNOWN(§4) 의 몫이다.

## 1T. 토큰 경계

### 1T.0 불변식 (T0)

> **T0. 코어 패키지의 어떤 코드 경로도 LLM 을 부르지 않는다. 한 주기 동안 LLM 호출 수 = 0, 예외 없음.**
> LLM 은 [1] 의도 파서와, 코어가 멈춘 뒤 임무 관리자가 부르는 임무 재구성(§4.3)에서만 불린다.

토큰이 쓰이는 자리는 사용자 설계의 셋에서 **둘로 줄인다.** "알 수 없는 상황" 은 코어 안에서 LLM 없이
안전 대체로 닫는다(§4). LLM 으로 가는 것은 그 결과 *임무가 불가능해졌을 때* 의 재구성뿐이고, 그것은
"알 수 없는 상황 처리" 가 아니라 "새 임무 컴파일" 이다.

### 1T.1 시험으로 붙드는 법 — 세 겹

한 겹만으로는 거짓 초록이 난다(글자 검사는 우회 경로를 못 본다). 세 겹을 같이 둔다.

| 겹 | 무엇을 | 어떻게 | 놓치는 것 |
|---|---|---|---|
| **정적** | `mba/core/**` 의 import 그래프 | AST 로 모든 `import`/`from` 을 모아 **허용 목록**(표준 라이브러리 일부: `dataclasses`, `enum`, `hashlib`, `struct`, `array`, `typing`, `mba.core.*`, `mba.ir.*`)과 대조. `socket`, `http`, `urllib`, `ssl`, `subprocess`, `importlib`, `anthropic`, `openai`, `google.*`, `mba.front.*` 는 빨간불. `__import__`·`eval`·`exec` 호출도 빨간불 | 허용된 모듈을 통한 우회(가능성 낮음), C 확장 |
| **실행 계수** | 주기당 LLM 호출 수 | LLM 은 `mba/front/llm.py` 의 한 함수로만 부른다. 그 함수가 전역 계수기를 올린다. 시험 하니스가 `cycle()` 전후 계수기를 재고 **차이 == 0** 을 단언. 수백 판 시뮬 전 주기에 대해 | 계수기를 거치지 않는 직접 호출(→ 정적 겹이 막음) |
| **망 차단** | 프로세스 전체 | WALP 의 `walp/nollm/sitecustomize.py`(33줄)와 `walp/nollm/claude` 를 그대로 가져온다. LLM 호스트 DNS 를 막고 시도를 로그에 적는다. 시험이 끝나면 **로그가 비어 있어야** 초록 | 차단 목록에 없는 호스트, 로컬 모형 |

C/C++ 방출물(§3.2)에는 추가로: 링크된 심볼에 `socket`/`connect`/`getaddrinfo` 가 없는지 `nm` 으로 본다.

**이 시험이 빨갛게 되는 것을 먼저 본다.** 코어에 일부러 `import urllib.request` 한 줄과 `llm.call()` 한 줄을
넣은 변형에서 세 겹이 각각 빨개지는지 확인한 뒤에야 초록을 믿는다.

### 1T.2 [1] 의 안쪽 — LLM 은 마지막 수단

[1] 도 순서가 있다.

1. **결정적 파서** — 기호표의 어휘(동의어 포함)로 슬롯을 채운다. WALP `walp/strips.py:170-187` (`계획`)
   과 `walp/src/parser.cpp` 가 이 꼴이다(정규식 · 어휘, LLM 없음). 다 채우면 토큰 0 으로 끝.
2. **거부 시에만 LLM** — 출력은 자유 문장이 아니라 §2.4 의 `MISSION` 문법으로 **제약된** 문자열이다.
   컴파일러가 문법 · 기호 존재 · 타입을 검사하고, 통과 못 하면 사용자에게 되묻는다(재시도 1회까지).
3. LLM 출력은 **어휘 밖의 기호를 만들 수 없다.** 새 `TARGET` 이 필요하면 거부하고 사람에게 넘긴다.

알려진 비용: WALP `walp/llmfront.py:10-12` 가 잰 대로, 싼 앞단은 **잘못 끝내는** 말을 낸다(그 실측에서
60 문장 중 9~10). 결정적 파서가 틀리게 "다 채웠다" 고 하면 LLM 을 안 부르고 틀린 임무가 나간다. 그래서
[1] 은 컴파일된 `MISSION` 을 **사람에게 한 줄로 되보여 주고**(정준형 DSL 문자열) 확인을 받는 선택지를 둔다
— 결정 사항 D3.

## 2. IR

### 2.1 기호표

모든 것은 기호 ID 이고, 이름은 사람과 로그를 위한 것이다. 코어는 이름을 보지 않는다.

| 접두 | 뜻 | 코어 표현 | 예 |
|---|---|---|---|
| `S##` | 상태 술어 — 참/거짓 | 상태 벡터의 비트 하나 (`uint64` 여러 워드) | `S17 CAMERA_DEGRADED`, `S23 RADAR_AVAILABLE`, `S41 TARGET_UNCERTAIN` |
| `E##` | 사건 — 비트의 상승/하강 또는 외부 신호 | 사건 비트 집합 (주기마다 새로) | `E07 CAMERA_BAD` = ↑`S_CAM_QUALITY_LOW` |
| `A##` | 행동 — 플랫폼 명령 하나 | `uint16` 코드 + 인자 2개 | `A04 SWITCH_RADAR`, `A08 MOVE_FORWARD`, `A12 OBSERVE` |
| `F##` | 고장 모드 — 부품의 비정상 모드 | 부품별 모드 열거 | `F01 CAM_POWER_LOSS` … |
| `C##` | 부품 | 모드 변수 하나 | `C01 CAMERA` |
| `B##` | 행동층 | 우선순위 정수 | `B00 SAFETY` … `B50 EXPLORE` |
| `R##` | 규칙 | 기록에 남는 ID | WALP `DecisionRecord.rule_id` 와 같은 역할 |
| `G##` | 모형 조각 | 부품·전이·규칙 묶음 | `G03 카메라 열화 모형` |
| `M##` | 임무 | 임무 레코드 | `M01` |

**번호 규칙.** 번호는 소스에 **명시** 한다(자동 배정 안 함). 이유: 로그 · 캐시 키 · C 표가 번호로 묶이는데,
선언 순서가 바뀌어 번호가 밀리면 옛 로그를 못 읽는다. 컴파일러는 중복 · 빈 번호 참조 · 접두와 종류 불일치를
오류로 낸다.

**비트 배정.** `S##` 는 컴파일러가 비트 위치를 배정한다(번호 ≠ 비트 위치). 같은 원뿔에 드는 비트를 같은
워드에 모아 원뿔 마스크 연산을 워드 하나로 끝내게 하는 것이 목적이다. 배정표는 IR 에 포함해 고정한다.

### 2.2 임무 레코드

```
GOAL       ∈ {SEARCH, CONFIRM, RETURN, HOLD, …}       — 기호
TARGET     = 대상 술어의 곱 (TYPE, COLOR, BRAND …)    — 기호, ANY 가능
ENV        = 환경 사전(priors)                        — 예: SMOKE, DARK
PREFERENCE = 위험 수준 · 제약                         — 예: LOW_RISK, AVOID(zone)
        ──▶  MISSION M01 { GOAL=SEARCH TARGET=OBJECT(color=BLUE) ENV=SMOKE RISK=LOW }
```

임무 레코드가 코어에 주는 효과는 셋뿐이다 — 그 외에는 아무것도 못 바꾼다.

1. **초기 상태 비트**: `ENV=SMOKE` → `S_SMOKE_PRIOR=1` (관측이 아니라 사전이라는 것을 비트 이름으로 구분한다).
2. **행동층 가동/억제**: `GOAL=SEARCH` → `B30 SEARCH` 가동, `B40 EXPLORE` 가동.
3. **파라미터 선택**: `RISK=LOW` → 미리 컴파일된 파라미터 묶음 중 하나(귀환 여유 · 확정 증거 수 등).
   새 수를 만들지 않고 **고른다.**

안전층의 한계값은 임무로 못 바꾼다(WALP `interfaces.hpp:97-124` 의 `kRuleLocked` 와 같은 원칙).

### 2.3 모형 조각

부품마다: 모드(정상 · 고장 모드 · UNKNOWN), 의존(다른 부품 · 환경), 관측(어떤 `S` 비트로 보이는가),
모드별 예측(그 모드면 관측이 어떻게 나와야 하나), 전이 규칙(명령이나 사건으로 모드가 바뀌는 길).

**의존 원뿔** `cone(C)` = `C` 에서 `DEPENDS` 를 따라 닿는 부품 전부(이행 폐포) ∪ 그 부품들이 관측하는 `S` 비트.
컴파일 때 미리 계산해 부품마다 비트 마스크로 저장한다.

### 2.4 DSL 문법 (EBNF)

목표: Model → State → Event → Policy → Action 을 한 파일에 선언하고, 컴파일러가 전부 표로 바꿀 수 있을 만큼
작게. 식(expression)은 비트의 논리곱 · 논리합 · 부정과, 관측 원자료에 대한 **임계값 비교** 만 허용한다.
루프 · 함수 · 산술 대입은 없다(그래야 정책 조회가 표가 된다).

```ebnf
file          = { decl } ;
decl          = symbol | component | observe | event | mission
              | behavior | arbitration | safety | fragment ;

(* ---------- 기호 ---------- *)
symbol        = "SYMBOL" sid ident [ string ] ";" ;
sid           = sprefix digit digit [ digit ] ;
sprefix       = "S" | "E" | "A" | "F" | "C" | "B" | "R" | "G" | "M" ;

(* ---------- 모형 ---------- *)
component     = "COMPONENT" sid ident "{" { comp_item } "}" ;
comp_item     = "MODES" mode { "," mode } ";"
              | "DEPENDS" "ON" sid { "," sid } ";"
              | "OBSERVED_BY" sid { "," sid } ";"
              | "PREDICT" mode_ref ":" guard ";"            (* 그 모드면 참이어야 할 관측 *)
              | "TRANSITION" mode_ref "->" mode_ref "ON" ( sid | "CMD" sid ) ";" ;
mode          = ( "NOMINAL" | sid | "UNKNOWN" ) [ "PRIOR" rank ] ;
mode_ref      = "NOMINAL" | sid | "UNKNOWN" ;
rank          = digit ;                                     (* 0 = 가장 그럴듯. 확률이 아니라 순위 *)

(* ---------- 상태 ---------- *)
observe       = "OBSERVE" sid "=" raw cmp number [ "FOR" int "TICKS" ] ";"
              | "PRIOR"   sid "=" "MISSION" "." ident "==" ident ";" ;
raw           = ident "." ident ;                           (* 플랫폼 원자료 채널 *)
cmp           = "<" | "<=" | ">" | ">=" | "==" | "!=" ;

(* ---------- 사건 ---------- *)
event         = "EVENT" sid "=" ( "RISE" sid | "FALL" sid | "EXTERNAL" ident ) ";" ;

(* ---------- 임무 ---------- *)
mission       = "MISSION" sid "{" { kv } "}" ;
kv            = ident "=" ( ident | ident "(" kv { "," kv } ")" ) ;

(* ---------- 정책 ---------- *)
behavior      = "BEHAVIOR" sid ident "PRIORITY" int [ "ENABLED_BY" guard ] "{" { rule } "}" ;
rule          = "RULE" sid [ "ON" sid { "|" sid } ] "WHEN" guard "DO" action ";" ;
action        = sid [ "(" arg [ "," arg ] ")" ] | "PASS" ;   (* PASS = 이 층은 이번에 낼 것 없음 *)
arg           = int | ident ;
guard         = conj { "|" conj } ;
conj          = lit { "&" lit } ;
lit           = [ "!" ] ( sid | "MODE" "(" sid ")" "==" mode_ref | "MISSION" "." ident "==" ident
                         | "TRUE" | "(" guard ")" ) ;

(* ---------- 중재 · 안전 ---------- *)
arbitration   = "ARBITRATION" sid { ">" sid } ";" ;          (* 왼쪽이 이긴다 *)
safety        = "SAFETY" "{" { veto | fallback } "}" ;
veto          = "VETO" sid { "," sid } "WHEN" guard "REASON" ident ";" ;
fallback      = "FALLBACK" "WHEN" guard "DO" action ";" ;

(* ---------- 조각 ---------- *)
fragment      = "FRAGMENT" sid ident "RELEVANT" sid { "," sid } "{" { decl } "}" ;
```

**컴파일러가 거부해야 하는 것(정적 검사).**

1. **정책 전체성** — 가동된 행동층들의 규칙과 맨 아래 기본 규칙을 합쳐, 모든 상태 벡터에서 승자가 하나
   나와야 한다. 맨 아래 층에 `WHEN TRUE` 규칙이 없으면 오류. (그래서 "정책 표에 없는 상태" 는 실행 중 나올
   수 없다 — UNKNOWN 은 정책이 아니라 **진단** 에서만 난다, §4.)
2. **한 층 안의 겹침** — 같은 층에서 두 규칙의 guard 가 동시에 참일 수 있으면 오류(먼저 쓴 것이 이긴다는
   암묵 규칙을 두지 않는다). 겹침은 guard 를 BDD/진리표로 펼쳐 검사한다 — 관련 비트가 많으면 비싸다(§3.3).
3. **안전 우회** — `SAFETY` 블록 밖에서 `VETO` 대상 행동을 무조건 내는 규칙은 경고(오류는 아님: 어차피 안전층이
   막는다). 안전층 자체의 `FALLBACK` 은 VETO 될 수 없는 행동이어야 한다(그렇지 않으면 오류).
4. **원뿔 무결성** — `PREDICT` 가 참조하는 비트가 그 부품의 원뿔 밖이면 오류.
5. **기호 타입** — `DO` 뒤에는 `A##` 만, `ON` 뒤에는 `E##` 만, `MODE(·)` 안에는 `C##` 만.

#### (c) `CAMERA_BAD` 의 국소 진단 — 원뿔만 깨운다

`E07 CAMERA_BAD` 가 켜지면 [5] 는 `cone(C01) = {C01, C05, C06, C07, C08}` 와 그 관측 비트
`{S10, S11, S12, S13, S22}` 만 본다. **레이더 · GPS · 배터리 모형은 이 주기에 읽지도 않는다.**
(단, `C05 POWER_BUS` 는 `C02 RADAR` 와 공유된다 — 공통 원인이 원뿔에 들어오는 길은 이것뿐이다.)

후보 생성은 사전 순위 순서로, 관측과 모순되는 것을 지운다(일관성 기반 진단의 단일 고장 가정):

| 후보 (단일 고장) | 예측 | 지금 관측 | 판정 | 비용 |
|---|---|---|---|---|
| Power? `C05=F05` | `S12` | `S12=0` | **기각** | 이미 있는 비트 — 0 |
| Data? `C06=F02` | `S13` | `S13=0` | **기각** | 0 |
| Lens? `C07=F03` | 위치를 바꿔도 `S11` 유지 | 모름 | 보류 | 판별 행동 필요 |
| Environment? `C08=F04` | `S22=1` 이고 위치·거리에 따라 `S11` 변동 | `S22=1` | 보류(우세) | 판별 행동 필요 |
| Camera 자체 `C01=F01` | `S10` | `S10=0` | **기각** | 0 |

남은 두 후보(Lens / Environment)를 가르는 행동을 [5] 가 **제안**한다: `A08 MOVE_FORWARD` 후 `A12 OBSERVE`
(연기 농도는 위치에 따라 변하고 렌즈 오염은 안 변한다는 모형 가정). 제안은 [6] 의 한 행동층(`B25 DIAGNOSE`)
의 출력일 뿐, 안전층과 중재를 똑같이 지난다.

진단 결과는 모드가 아니라 **파생 비트** 로 정책에 넘어간다:

```
C08=F04 (또는 Lens/Env 미결) & C01=NOMINAL  →  S17 CAMERA_DEGRADED = 1,  S43 CAMERA_FAILED = 0
C02=NOMINAL & S14                           →  S23 RADAR_AVAILABLE = 1
후보 물체가 있으나 색 미확정                  →  S41 TARGET_UNCERTAIN = 1
```

여기서 **사용자 설계의 `(S17, S23, S41) → A04 SWITCH_RADAR`** 가 정책 표의 한 칸으로 떨어진다.

**설계상 걸리는 점 하나(정직하게):** 레이더는 **색을 못 본다.** "파란" 물체를 확정하려면 결국 카메라가 필요하다.
그래서 이 임무의 정책은 "레이더로 바꾼다" 로 끝나지 않고 — 레이더로 후보를 찾고(`SEARCH`) → 가까이 가서
(`TARGET_NEAR`) → 카메라로 근거리 확인(`TARGET_CONFIRM`) — 이어야 한다. 연기 속 근거리에서도 카메라가
색을 못 내면 `S41` 이 꺼지지 않고, 그때는 **확정하지 않는다**(WALP `state.cpp:225-233` 이 근거 없는 확정을
막는 것과 같은 원칙). 이것을 모형으로 못 적으면 "토큰 0 으로 연기 속 파란 물체를 찾는다" 는 문장은 거짓이다.

풀어 적어야 한다.)

**결정 사항 D1 — `DIAGNOSE` 층의 자리.** 사용자 순서 `SAFETY > RETURN > TARGET_CONFIRM > SEARCH > EXPLORE`
에는 진단의 판별 행동이 없다. 위 초안은 `TARGET_CONFIRM` 과 `SEARCH` 사이에 넣었다. 판별 행동이 탐색보다
앞서지만 확정·귀환보다는 뒤라는 뜻이다.

**결정 사항 D2 — `RETURN` 과 `CONFIRM` 의 순서.** WALP 는 반대 순서다: 확정 선언이 귀환보다 앞선다
(`walp/src/planner.cpp:294-306` 이 `:308-323` 보다 먼저). 이유는 선언이 에너지를 거의 안 쓰고, 안전층의
에너지 하한이 따로 있기 때문이다(`state.cpp:221-223` 은 Observe·Hold 에도 귀환 여유를 검사한다).
사용자 순서대로 `RETURN > TARGET_CONFIRM` 이면 배터리가 문턱을 넘는 순간 눈앞의 확정 물체를 선언하지 않고
돌아선다. 어느 쪽인지 사용자가 정해야 한다.

## 3. 컴파일 대상

### 3.1 1단계 — 파이썬 참조 해석기

- **목적은 속도가 아니라 정답 기준(oracle)** 이다. C 방출물은 같은 입력 열에서 이것과 **비트 단위로 같은**
  행동 열을 내야 한다(차분 시험).
- **결정성:** 같은 `IR 해시` + 같은 관측 열 + 같은 씨앗 → 같은 행동 열. 해석기 안에 난수 · 벽시계 · 딕셔너리
  순회 순서 의존을 두지 않는다(규칙은 번호순, 후보는 (사전순위, 번호)순). 행동 열의 해시를 시험이 비교한다.
- 모든 결정은 WALP `DecisionRecord`(`walp/include/walp/types.hpp:147`)처럼 `(tick, rule_id, behavior,
  action, reason, 원뿔ID, 캐시 hit/miss, IR 해시)` 한 줄로 남긴다.

### 3.2 2단계 — C/C++ 표 방출기

- 출력은 **상수 표 + 작은 고정 해석 루프** 이다. 동적 할당 없음, 재귀 없음, 망 없음.
- 방출물: `state_bits[]`(비트 배정), `obs_thresholds[]`, `event_edges[]`, `rules[]`(아래), `behavior_order[]`,
  `cone_mask[C]`, `relevance_index[]`, `veto[]`, `fallback[]`, `ir_hash`.
- WALP 의 C++ 코어(`walp/src/executive.cpp:63-187`, `walp/include/walp/interfaces.hpp:97-124`)가 이미 이 형태의
  절반이다 — 정책을 데이터(`rule_action[RC_COUNT]`)로, 잠긴 규칙을 `kRuleLocked` 로 두었다.

### 3.3 상태 부호화와 정책 조회 — "O(1)" 이 정확히 무슨 뜻인가

상태 = `S` 비트 벡터(`uint64` × W). 규칙 하나 = `(event_mask, care_mask, value_mask, action)`.
규칙이 맞는다 ⇔ `(E & event_mask) != 0 or event_mask == 0` 이고 `(S & care_mask) == value_mask`.
(guard 의 `|` 는 컴파일러가 규칙을 여러 개로 펼친다 — DNF.)

조회는 두 가지 중 하나로 방출한다.

| 방식 | 조건 | 비용 |
|---|---|---|
| **조밀 표** `T_b[idx]` | 행동층 `b` 의 규칙이 쓰는 비트의 합집합 `U_b` 가 작을 때(기본 상한 `|U_b| ≤ 12` → 4096칸) | 비트 모으기(pext 또는 시프트 표) + 배열 읽기 1회 |
| **마스크 목록** | `|U_b|` 가 크면 | 층의 규칙 수 `K_b` 만큼 마스크 비교 |

중재는 층 순서대로 첫 non-PASS 를 고른다: 최대 `B` 층.

**그래서 "O(1)" 은 "모형 크기나 세계 크기에 무관하고, 컴파일 때 정해진 상수 `Σ K_b`(또는 `B`) 로 위가 막힌다"
는 뜻이다.** 상태 공간 전체(2^|S|)의 표를 만든다는 뜻이 아니다 — 그것은 불가능하다. 상수가 작다는 것은
보장이 아니라 **설계 제약** 이고, 컴파일러가 `K_b`·`|U_b|` 를 출력해 사람이 보게 한다.

사용자 설계의 `policy[state][event]` 표기는 개념으로 맞지만, 실제 열쇠는 "전체 상태" 가 아니라 "그 층이
보는 비트" 다. 이 사영(projection)이 표를 작게 하는 유일한 장치다.

### 3.4 증분 진단의 상한 — 무엇이 보장되고 무엇이 안 되나

**보장(컴파일 때 계산되는 상한):**

- 사건 `E` 가 부품 `C` 에 걸리면 진단 작업은 `cone(C)` 안의 부품 수 `n_C` 와 부품당 모드 수 `m` 에 대해
  단일 고장 가정에서 후보 `≤ n_C · m`, 후보당 `PREDICT` 검사는 원뿔 마스크 연산 몇 번.
- `n_C` 는 컴파일러가 부품마다 출력한다. 상한을 넘는 원뿔(예: `> 16`)은 경고.
- 사건이 없는 주기에는 진단기가 **돌지 않는다.** 믿음 캐시([4])가 원뿔 비트가 안 바뀐 경우를 걸러낸다.

**보장하지 않는 것 — 명시한다:**

1. **다중 고장.** 단일 고장 가정이 기본이다. 두 고장이 동시에 나면, 단일 후보가 전부 기각되어 **빈 후보 집합 →
   UNKNOWN** 으로 간다(§4). `k=2` 까지 넓히는 선택지는 있으나 후보 수가 `C(n_C·m, 2)` 로 늘고, 그 이상은
   하지 않는다. → 결정 사항 D4.
2. **원뿔 밖의 원인.** 모형에 의존이 빠져 있으면(예: 카메라와 레이더가 같은 열 문제로 같이 나빠지는데 그 공통
   원인이 모형에 없음) 원뿔이 그것을 못 본다. 증분 진단의 정확성은 **모형의 의존 그래프만큼만** 맞다.
3. **고장이 숨는 경우.** 관측이 정상을 보고하는데 실제로는 고장(WALP 시뮬의 `act_silent`, `walp/sim/world.hpp:27`)
   이면 사건이 안 켜지고, 진단이 아예 안 깨어난다. 이것은 원뿔 문제가 아니라 관측 가능성 문제다.
4. **간헐 고장 · 진동.** `FOR n TICKS` 지연으로 완화할 뿐, 사건이 켜졌다 꺼졌다 하면 진단이 반복된다. 캐시가
   비용은 줄여도 판정의 안정성은 보장 못 한다.
5. **원뿔이 모형 대부분이면** 증분의 이득이 없다. 공유 전원 버스처럼 허브 부품이 있으면 원뿔이 커진다 —
   이 경우 이득은 0 에 가깝다는 것을 측정에서 따로 보고해야 한다(§6.3).
6. **사전 순위는 확률이 아니다.** 순위가 틀리면 판별 행동이 늘 뿐 결론은 같아야 하지만, 판별 행동이 없는 경우
   (두 후보가 모든 가능 관측에서 같은 예측) 순위가 결론을 정한다. 컴파일러가 "구별 불가능한 후보 쌍" 을
   목록으로 낸다.

이 진단은 Livingstone 계열의 모드 식별을 **크게 단순화한** 것이다(충돌 지향 최적 우선 탐색 대신 원뿔 안 사전순위
나열) [미확인 — 선행조사에서 대조]. 단순화의 대가는 위 1·6 이다.

## 4. UNKNOWN 처리

### 4.1 UNKNOWN 은 어디서 나는가

정책은 컴파일 때 전체성이 검사되므로 "정책에 없는 상태" 는 없다. UNKNOWN 은 **진단** 에서만 난다:

- **U1** 원뿔 안 단일 고장 후보가 전부 기각(관측을 설명하는 모드가 없음)
- **U2** 판별 행동을 다 썼는데 후보가 둘 이상 남음(구별 불가)
- **U3** 관측 자체가 낡거나 없음(WALP `state.cpp:86-96` 의 stale 과 같은 부류)

### 4.2 토큰 없는 닫기 (코어 안)

```
UNKNOWN 감지
  → (1) 안전 대체:  안전층 FALLBACK — 귀환이 가능하면 A01, 아니면 A00 SAFE_HOLD
                    (WALP state.cpp:276-300 의 fallback 이 "귀환이 에너지로 가능할 때만 걷고 아니면 멈춘다")
  → (2) 관측:       A12 OBSERVE, 최대 k_obs 번 (기본 3, 임무 파라미터)
  → (3) 믿음 갱신:  원뿔을 한 단계 넓힌다 (cone 반경 +1). 최대 r_max 단계, 마지막은 전체 모형
  → (4) 알려진 상태로:
        - 일관 후보가 생기면 → 그 모드 비트를 켜고 정상 정책으로 복귀
        - 그래도 없으면 → 그 부품을 MODE=UNKNOWN 으로 고정하고 "쓸 수 없음" 비트를 켠다.
          남은 능력으로 임무가 가능한지 **가능성 검사**(아래)를 돌린다.
              가능 → 정상 정책으로 복귀 (예: 카메라 UNKNOWN 이면 S43=1 → TARGET_CONFIRM 이 PASS)
              불가능 → (5)
  → (5) 임무 불가능: RETURN 또는 SAFE_HOLD 로 고정. 여기서 처음으로 코어 밖 임무 관리자에게 넘긴다.
```

**임무 가능성 검사** 는 컴파일 때 만든 표다: 임무의 각 필수 능력(예: `CONFIRM_COLOR`) → 그것을 줄 수 있는
부품 조합. 부품 하나가 UNKNOWN 이 되면 그 표를 한 번 읽는다. 토큰 0.

### 4.3 LLM 으로 가는 유일한 길 — 임무 재구성

- **언제:** (5) 에 닿았고, 사람이 미리 `ALLOW_RECONFIG` 를 임무에 켰을 때만. 기본은 꺼짐 — 꺼져 있으면 사람에게
  보고하고 끝.
- **무엇을:** 코어가 `SAFE_HOLD`/`RETURN` 에 고정된 상태에서, 임무 관리자가 [1] 을 부른다. 입력은 **기호만**:
  원래 `MISSION`, UNKNOWN 이 된 부품 목록, 가능성 검사의 실패 항목. 출력은 새 `MISSION` 하나(같은 문법).
  예: `TARGET=OBJECT(color=BLUE)` → `TARGET=OBJECT(any) & REPORT_CANDIDATES` (색 확정 포기, 후보 위치만 보고).
- **검사:** 새 `MISSION` 은 처음과 똑같이 컴파일러를 지나야 한다. 새 기호를 만들 수 없고, 안전층 한계를 못 바꾼다.
  가능성 검사를 통과 못 하면 버린다.
- **예산(기본값 — 측정이 아니라 설정):** 임무당 재구성 1회, 호출당 입력·출력 토큰 상한(결정 사항 D5),
  실패 시 재시도 없음. 예산을 다 쓰면 `ABORT` + 사람에게 보고.
- **코어 쪽 불변식:** 재구성이 진행되는 동안 코어 주기는 안전 대체만 돌리고, 그 주기들의 LLM 호출 수도 0 이다
  (호출은 코어 프로세스/패키지 밖에서 일어난다). 새 IR 이 들어오면 코어는 **재시작** 한다 — 실행 중 IR 을
  부분 교체하지 않는다.

| **V4** | 진단 범위 | 진단기가 읽은 부품 집합 ⊆ `cone(C)`(계측으로 기록). 사건 없는 주기에 진단기 호출 0 | 원뿔 마스크를 전체 마스크로 바꾼 변형 → V4 빨강, 결과는 같아야 함 |
| **V5** | 정책 전체성·무겹침 | 컴파일러 정적 검사 + 시뮬 중 "승자 없음" 0회 | 기본 규칙을 지운 소스 → 컴파일 거부 |
| **V6** | 임무 재구성 예산 | 임무당 LLM 호출 ≤ (파서 1 + 재구성 예산), 토큰 상한 이하 | 예산 0 에서 재구성 시도 → 거부 |

V4 의 변형 시험은 중요하다: 원뿔을 전체로 넓혀도 **결론이 같아야** 하고(같지 않으면 원뿔이 원인을 잘라먹고 있다),
읽은 부품 수만 줄어야 한다. 결론이 다르게 나오는 경우가 바로 §3.4 의 "보장하지 않는 것" 의 실례이고, 그 목록을
측정으로 채운다.

### 6.2 토큰 절약을 주장하려면 — 측정 설계

**주장의 꼴:** "같은 과제 모음에서, MBA 는 성공 과제당 LLM 토큰이 비교군보다 적고, 성공률·안전 위반은 나쁘지
않다." 숫자는 없다 — 아직 아무것도 재지 않았다.

**과제 모음.** 격자 시험대(§5.1 확장)에서 자연어 명령 × 환경 × 고장 주입의 고정 모음. **사전 등록** 하고
봉인한다(명령 문장 · 씨앗 · 고장 비율). 모형 작성자가 모음을 보고 모형을 맞추면 안 된다 — 모형을 먼저 동결하고
모음을 연다.

**비교군 (최소 셋 — 하나만 두면 사소한 설명을 못 죽인다):**

| 비교군 | 무엇 | 왜 필요한가 |
|---|---|---|
| **L-tick** | 매 주기 LLM 이 행동을 고르는 에이전트 | 가장 흔한 꼴. 단 이것만 비교하면 허수아비 |
| **L-event** | 사건이 날 때만 LLM 을 부르고 그 사이엔 마지막 계획을 따르는 에이전트 | **강한 비교군.** "LLM 을 덜 부르면 토큰이 준다" 는 사소한 설명을 가른다 |
| **W0** | WALP 의 기존 실행기(토큰 0, 손 규칙, 모형 진단 없음) | "토큰 0" 자체는 손 코드 제어기도 낸다. MBA 의 기여가 *토큰* 이 아니라 *모형 기반 진단으로 넓힌 과제 범위* 인지 이것으로 가른다 |

**재는 것 (과제마다, 실패 포함):**

- 입력·출력 토큰을 **부품별로**: [1] 파서, 임무 재구성, (비교군의) 루프 안 호출. API 의 사용량 필드에서 읽는다
  (추정 금지).
- 성공 여부(시뮬 정답 대조), 안전 위반(시뮬 독립 계수), 스텝 수, UNKNOWN 진입 수, 재구성 횟수.
- **성공 과제당 토큰** = (실패 과제 포함 전체 토큰) / (성공 과제 수). 실패를 빼면 MBA 가 어려운 과제를 포기해
  유리해진다.
- **모형 작성 비용**: `.mba` 모형을 LLM 으로 썼다면 그 토큰을 따로 적고, 과제 수로 나눈 상각액을 같이 보고한다.
  사람이 썼으면 사람 시간을 적는다. 이것을 빼면 "토큰 0" 은 비용을 앞으로 옮긴 것일 뿐이다.
- **덮개율**: 과제 모음의 명령 중 [1] 이 컴파일에 성공한 비율, 결정적 파서만으로 끝난 비율.

**독립 대조.** 토큰 수를 두 길로 센다: API 사용량 필드 합계, 그리고 망 차단기(§1T.1) 로그의 호출 수 × 호출당
기록 토큰. 둘이 안 맞으면 보고하지 않는다.

### 6.3 무엇이 주장을 깨는가 (무효화 조건)

아래 중 하나라도 나오면 "토큰을 아낀다" 를 표제로 쓰지 않는다.

1. **성공률이 L-event 보다 유의하게 낮다.** 토큰이 적어도 일을 못 하면 아낀 것이 아니다. 성공 과제당 토큰으로
   보면 드러나야 하지만, 성공률 자체도 같이 표에 둔다.
2. **안전 위반이 0 이 아니다.** (V2 위반 — 주장 이전에 결함.)
3. **덮개율이 낮아 과제 대부분이 재구성/사람 넘김으로 간다.** 그러면 토큰은 루프에서 [1] 과 재구성으로 옮겨갔을
   뿐이다. 재구성 토큰을 포함한 합계로 판정한다.
4. **W0 과 성공률·위반이 같다.** 그러면 MBA 의 모형 기반 진단은 이 시험대에서 아무것도 더하지 않았다 — 토큰 0 은
   W0 도 이미 냈다. 이 경우 정직한 결론은 "이 시험대가 진단을 요구하지 않는다" 이고, 고장 주입을 늘린 모음으로
   다시 재야 한다.
5. **모형 작성 비용을 상각했을 때 L-event 보다 많다**(과제 수가 적은 영역).
6. **증분 진단의 이득이 없다** — 원뿔 크기가 모형 대부분이거나, V4 변형(전체 원뿔)과 계산량 차이가 측정 잡음
   안이면 "전체를 안 뒤진다" 는 주장을 빼고 "진단을 사건 때만 돌린다" 로 줄인다.
7. **비교군 L-tick/L-event 의 프롬프트를 MBA 에 불리하게(또는 유리하게) 짰다는 의심** — 프롬프트를 사전 등록에
   그대로 넣고, 비교군이 같은 정보(같은 관측 · 같은 임무)를 받는지 확인한다.

### 6.4 사소한 설명 — 재서 죽일 것

| 사소한 설명 | 재서 죽이는 법 |
|---|---|
| "토큰이 0 인 것은 LLM 을 안 불렀기 때문" (항진) | W0 비교. 기여를 토큰이 아니라 *같은 토큰 0 에서 넓힌 과제·고장 범위* 로 다시 적는다 |
| 과제가 너무 쉬워 정책 표 하나로 다 풀린다 | 과제 모음에 고장 주입·다중 센서 과제 비율을 사전 등록. 고장 없는 과제와 있는 과제를 갈라 보고 |
| 진단이 실제로는 안 깨어난다(사건 문턱이 안 넘음) | 판마다 사건·진단 호출 수를 기록. 0 이면 그 판의 진단 주장은 버린다 |
| 캐시 적중이 높은 이유가 상태가 안 바뀌어서 | 캐시 적중률을 상태 변화율과 같이 보고 |
| 비교군 LLM 이 프롬프트 길이 때문에 비싸다 | 비교군 프롬프트의 고정분/가변분 토큰을 갈라 적는다 |
