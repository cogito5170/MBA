# 결정 — Claude 앞단은 MBA(mba-front)를 쓴다

**날짜:** 2026-10-02 · **결정:** Claude 앞에 세우는 토큰 절감 앞단으로 **MBA(`mba-front`)를 쓴다.** walp-front 는 쓰지 않는다.

## 근거 — 같은 프롬프트 24 개 비교 (`docs/PREREG_비교_walp.md`, 실행 `cmp-20261002T020134`)

기준 커밋: walp-front = `cogito5170/walp` `bb0a754` · MBA = `cogito5170/MBA` `0780ac6`. 기준선 `claude -p` 24 회, haiku-4.5.

| | walp-front | **MBA** (캐시 + 작은 머리 컴파일) |
|---|---|---|
| LLM 토큰 (기준선 대비) | 0.658 | **0.510** |
| 틀린 가로챔 (사람의 일을 잃음) | **3** | **0** |
| 잃은 일을 `//` 로 다시 물은 비용까지 (사후 계산) | 0.800 | **0.510** |
| 저장소 질문 5 개 | 2 개 가로챔, 둘 다 틀림 | 5 개 모두 맞게 가로챔 |

MBA 가 **토큰을 더 줄이고, 틀리게 가로챈 것이 없다.** walp-front 의 틀린 가로챔은 "안녕! 17 곱하기 23은?" (인사만 답)과
"현재 HEAD 커밋 제목 알려줘" · "HEAD 커밋의 제목만 말해줘" (쓰는 법 안내로 답)였다 -- 사람의 요청을 잃는 쪽의 실패라
토큰보다 무겁게 본다.

## 이 결정이 기대는 범위 (과장하지 않는다)
- 프롬프트 24 개 · haiku 하나 · n=1. 묶음은 잡담 7 · 저장소 질문 6 · 반복 6 으로 짰다 -- 실제 사용의 비율이 아니다
- **잡담만 보면 walp-front 가 낫다**(7/7 을 토큰 0 · 지연 ~10ms 로). MBA 는 잡담을 거의 못 잡는다(1/7)
- **MBA 가 더 느리다** -- 가로채지 못한 프롬프트마다 컴파일(4~5초)이 붙어 지연 합 161.8초(기준선 122.0, walp-front 75.8)
- 둘을 함께 쓰면 토큰은 0.299 로 가장 적었지만 walp-front 의 틀린 가로챔 3 개를 그대로 가져간다 -- 그래서 함께 쓰지 않는다
- 22 번은 기준선도 판정을 못 넘어 규칙대로 뺐다

## 다음
1. 실사용에서는 `mba-front` 를 **그림자 모드**로 먼저 건다(`mba-front install-hook`) -- 실제 프롬프트에서 가로챔 비율 · 일치율을 잰다
2. `mba-front report --text` 에서 켜기 후보(판정된 제안 ≥ 10 · 일치율 ≥ 90%)인 종류만 `MBA_FRONT_MODE=on MBA_ENABLE=…` 로 켠다
3. 알려진 개선점: 직접 답한 질문의 답도 캐시에 넣기(같은 질문 두 번째에 다시 컴파일했다) · 저장소와 무관한 말은 상태 해시에 묶지 않기
4. **다시 볼 조건:** 실사용 그림자에서 MBA 의 틀린 가로챔이 나오거나, 잡담 비율이 높아 walp-front 의 몫이 커지면 이 결정을 다시 잰다
