## 팔 — 구조 3 × 머리 2

| 구조 \ 머리 | 기본 머리(Claude Code 시스템 프롬프트 + 도구 정의) | 작은 머리(지시 한 장, ~200자) |
|---|---|---|
| **루프**(LLM 이 Bash 로 끝까지) | LOOP | LOOPB (`--tools Bash --system-prompt AGENT_ROLE`) |
| **사건 도구**(내장 도구 없음, walp `walp_wait` · `walp_publish` 만 -- 강한 기준선) | EVENT | EVENTB |
| **MBA**(컴파일 한 번 + 토큰 0 실행 + 캐시) | MBA | BARE |

EVENT · EVENTB 는 T1 · T2 만(그 과제에만 사건 도구가 있다). 파일럿에서 EVENTB 가 실제로 walp 도구를 부르는 것을 확인했다
(V1 TOOL 팔은 6 회 모두 안 불러 기준선이 못 됐다).

실패로 셌던 회차 때문 -- 수를 보기 전에 바꾼다.

## 가르는 법

과제마다 평균 토큰 T(팔). 로그 비는 더해진다:

    log(LOOP/BARE) = log(LOOP/LOOPB)   [머리 몫, 루프에서]  + log(LOOPB/BARE) [구조 몫, 작은 머리에서]
                   = log(LOOP/MBA)     [구조 몫, 기본 머리] + log(MBA/BARE)   [머리 몫, MBA 에서]

두 길을 **둘 다** 적는다. 두 길의 머리 몫이 다르면 그 차가 상호작용이다(머리를 줄인 효과가 구조에 따라 다르다).
강한 기준선 대비 구조 몫: `EVENT/MBA`(기본 머리) · `EVENTB/BARE`(작은 머리).

## 가설 · 판정

- **H-head**: 같은 구조 안에서 작은 머리가 토큰을 줄인다(LOOP>LOOPB, MBA>BARE, EVENT>EVENTB)
- **H-struct**: 같은 머리 안에서 MBA 구조가 루프보다 적다(LOOP>MBA, LOOPB>BARE)
- **H-strong**: 같은 머리 안에서 MBA 구조가 사건 도구 기준선보다 적다(EVENT>MBA, EVENTB>BARE) -- T1 · T2
- 각 비교는 **범위가 겹치지 않고** 적은 쪽의 성공이 많은 쪽보다 나쁘지 않을 때만 "섰다". 겹치면 "차이 없음"
- 과제마다 따로. 한 수로 합치지 않는다

## 사소한 설명 — 재서 죽일 것
1. 작은 머리의 이득이 **지시문 내용**(예: "확인을 묻지 마라") 때문에 성공이 바뀐 것 -- 성공 수를 팔마다 적는다. 성공이 다르면
   토큰 비교를 그 쌍에서 주장하지 않는다
2. EVENT 의 이득이 **내장 도구 정의를 뺀 것**(머리가 작아짐) -- EVENT 와 LOOP 의 캐시 토큰을 따로 적는다
3. T4 의 0 은 정의상(V1 과 같다)
4. 캐시 데움 -- 팔 순서를 회차마다 돌린다(V1 과 같다)

- 한 쌍에서 성공 수가 다르면 그 쌍의 토큰 비교는 주장하지 않는다
