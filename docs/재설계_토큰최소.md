# MBA 재설계 — 목적함수 = LLM 토큰 최소

**초안 — 사용자 확인 뒤 코드에 반영한다.** 이전 설계(`설계.md`)는 로버 임무(연기 속 파란 물체)를 실례로 삼았다.
사용자 결정(2026-10-01): **MBA 의 목적은 "토큰 사용량을 최소로 쓰는 기계" 하나다.** 부품 [1]–[8] 의 구조는 그대로
두고, 모든 파라미터 변수를 **토큰 단위**로 다시 정의한다. 특정 플랜트(로버 · Claude Code)는 이 기계 위에 얹는
모형 파일일 뿐이다.

## 0. 목적함수와 토큰 등식

**최소화:**  `T = Σ_과제 tokens(과제)` — 새 입력 + 캐시 만들기 + 캐시 읽기 + 출력, **종류별로 따로 보고**한다.

**제약:**  성공률 ≥ 기준선 − δ,  잘못 자동 실행 ≤ ε,  바깥 동작 무단 0.
**동률 규칙:**  제약이 같으면 토큰이 적은 쪽. 문턱과 값이 정확히 같으면 토큰을 쓰지 않는 쪽(사용자 결정).

LLM 호출 한 번의 토큰은 네 항의 합이다.

```
tokens(호출 i) = P  +  C_i  +  I_i  +  O_i
                 │      │      │      └ 출력
                 │      │      └ 이번에 새로 넣은 것(질문)
                 │      └ 같이 실려 간 맥락(대화 이력 · 문서 · 도구 결과)
                 └ 고정 머리(시스템 프롬프트 · 도구 정의 · 지시문) — 호출마다 다시 실린다
T = N_호출 × P̄  +  Σ C_i  +  Σ I_i  +  Σ O_i   (+ 틀린 답의 재시도)
```

**잰 것(이 등식의 각 항이 실제로 어디에 있는지):**

| 항 | 실측 | 출처 · 한계 |
|---|---|---|
| P (고정 머리) | `claude -p "Reply with exactly: OK"` 한 번 = **28,410 토큰**(캐시 읽기 23,133 · 캐시 만들기 5,211 · 입력 10 · 출력 56) | 이 컨테이너, 2026-10-01, haiku-4.5, **1 회**. 답이 "OK" 두 글자여도 호출 한 번에 2.8만 |
| C (맥락) | 주 세션 턴당 맥락 평균 **419k**, 캐시 읽기 98.6% | `walp/docs/실행정책층/추적_이세션.json`, 세션 하나 |
| N (호출 수) | 1,456 턴 중 루틴 40% · stop 훅이 부른 턴 9.3% · 연쇄 덧턴 13.8% · 기다리기 11.1% | 같은 파일. 분류기가 읽기 전용 git 도 루틴으로 세어 부풀었을 수 있다(토큰 감사 B) |
| P 의 중복 | 하위 에이전트 셋이 턴 1 에 각 ~59k 를 캐시 읽기 0 으로 새로 씀 | 이 세션 추적(토큰 감사 B) |
| O | 전체의 0.29% | 추적_이세션.json |

→ **지렛대 순서: N(호출 수) > P(고정 머리) > C(맥락) ≫ O(출력).** 출력 줄이기(P4 출력 예산)는 walp 에서 이미
실패로 판정됐다(`PREREG_P4_출력예산.md`: H1 안 섬). 그래서 이 설계의 변수 대부분은 N · P · C 에 걸린다.

## 1. 부품별 파라미터 변수 — 전부 토큰으로

표기: **[변수] 단위 · 기본값 · 무엇을 줄이나 · 어떻게 재나**. 기본값은 설정이지 측정이 아니다.

### [1] 의도 컴파일러 — 토큰을 쓸 수 있는 첫 자리

| 변수 | 단위 · 기본 | 줄이는 항 | 잼 |
|---|---|---|---|
| `coverage` 결정적 파서 적중률 | 비율 · (잼) | N | 봉인 문장 모음에서 LLM 없이 다 채운 비율 |
| `θ_p` LLM 호출 문턱 | 확률 · 0.8 | N, 재시도 | `p > θ_p` 일 때만 부른다. `p == θ_p` 면 안 부름 |
| `prior(a,b)` 자리별 사전 | 베타 · (1,1) | — | 냉시작 값. **(1,1) 이면 p=0.5 < 0.8 이라 처음엔 영영 안 부른다** → 결정 D-R1 |
| `P_profile` 호출 머리 | 토큰 · `bare` | **P** | 컴파일 호출은 도구 · 대화가 필요 없다. CLI 머리(2.8만) 대신 맨 API + 문법 한 장. 머리 크기를 잰다 |
| `C_send` 실어 보낼 맥락 | 토큰 · 기호만 | **C** | 대화 이력을 보내지 않는다(무상태). 허용 값 목록 + 빈칸 이름만 |
| `O_max` 출력 상한 | 토큰 · 64 | O | `KEY=VALUE;…` 한 줄 문법. 넘으면 잘라 검증 실패로 센다 |
| `retry_max` | 회 · 0 | 재시도 | 틀리면 다시 묻지 않고 사람에게 |

### [2] 압축 기호표

| 변수 | 단위 · 기본 | 줄이는 항 | 잼 |
|---|---|---|---|
| `sym_width` 기호 하나의 크기 | 토큰 · ≤ 2 (`S17` 꼴) | C, I | LLM 에 보내는 모든 것은 ID 로. 자연어 설명은 기호표에만 두고 보내지 않는다 |

### [3] 사건 / 상태 기계 — 정상 운용의 토큰 = 0

| 변수 | 단위 · 기본 | 줄이는 항 | 잼 |
|---|---|---|---|
| `debounce` 사건 지연 | 주기 · 3 | N | 같은 사건이 깜빡여 LLM 을 거듭 부르지 않게(`FOR n TICKS`) |
| `replan_on` 다시 계획할 때 | 사건 집합 · 임무 불가능만 | N | 사건이 없으면 LLM 경로에 닿지 않는다. 주기당 LLM 호출 = 0 (T0 시험) |

### [4] 믿음 캐시 — 같은 질문 · 같은 답

| 변수 | 단위 · 기본 | 줄이는 항 | 잼 |
|---|---|---|---|
| `qkey` 질문 정준형 | 해시 · 어순·조사·어미 제거 | N | 같은 말의 다른 꼴을 한 열쇠로 |
| `state_key` 상태 열쇠 | 해시 · 원뿔 비트 | N | 상태가 같으면 답이 같다(P1 의 일반형). 상태가 바뀌면 그 칸만 무효 |
| `agree_min` 동치류 확인 | 개 · 2 | N | 다른 질문 꼴 두 개 이상이 같은 정준 답으로 검증돼야 동치류로 재사용(WALP 답 캐시 6/43 오답의 교훈) |

### [5] 고장 모형 — "고장" = 토큰이 새는 모드

| 모드 | 감지 비트(센서) | 토큰 0 처방 | 잰 몫(상한) |
|---|---|---|---|

| 루틴 연쇄 | 커밋 ∧ 미발행 | 매크로 한 번 | 연쇄 덧턴 13.8% · 재생 P2 9.6% |

## 2. 무엇이 "줄었다" 의 증거인가 — 측정 설계

같은 과제 묶음을 두 길로 돌려 **과제당 토큰(실패 포함)** 을 비교한다.

| 팔 | LLM 이 불리는 곳 |
|---|---|
| L-loop (기준선) | 매 걸음(지금의 에이전트 루프) |
| L-event | 사건 때만(강한 기준선 — 이것을 못 이기면 기여가 없다) |
| MBA | 관문(`p > θ_p`)을 지난 컴파일 · 재구성뿐 |

- **먼저 계기를 검증한다:** 토큰 계기(`meter`)가 공급자 기록과 맞는지(R4, 차 ≤ 5%). 맞기 전에는 아무 차이도 말하지 않는다.
- 보고: 토큰 종류별 · 과제별 · 성공률 · 모형 작성 상각분. "토큰 0" 은 손 코드 제어기도 내므로, 손 코드(WALP 실행기)를 셋째 기준선으로 둔다.
- **무효화:** L-event 와 차이가 잡음 안이면 · 성공률이 δ 넘게 떨어지면 · 상각을 넣으면 뒤집히면 · 동치류 재사용이 오답을 내면(1 건이라도 보고).
