# 사전등록 — MBA 앞단 대 walp-front 앞단, 같은 프롬프트 묶음

**수를 보기 전에 커밋한다.** 하니스 `bench/compare_walp.py`.

**비교 기준 커밋(각 저장소 main 의 최신):** walp-front = `cogito5170/walp` `bb0a754`(llmfront.py 마지막 변경 `a2be5b9`) · MBA = `cogito5170/MBA` `0780ac6`. 별도 저장소 `cogito5170/walp-front` 는 없다 -- walp-front 는 walp 안의 도구다.

## 물음
Claude 앞에 세우는 두 앞단 -- walp-front(잡담층 · 잡담이면 토큰 0 으로 답한다)와 MBA(같은 질문 + 같은 저장소 상태면 캐시,
아니면 작은 머리 컴파일 -> 닫힌 연산) -- 이 같은 프롬프트 24 개에서 **LLM 토큰을 얼마나 줄이고, 몇 번 틀리게 가로채는가.**

## 설계 -- 아래 흐름(Claude)을 한 번만 돌려 모든 팔이 같은 것을 쓴다
1. **기준선**: 프롬프트 24 개를 정해진 순서대로 임시 git 저장소에서 `claude -p`(기본 머리, haiku-4.5) 로 돌린다.
   프롬프트마다 답 · 토큰(결과 JSON usage) · 지연 · 전후 저장소 상태 해시를 적는다. 자식에는 `MBA_FRONT_MODE=off`
   (이 컨테이너에 설치된 mba-front 그림자 훅이 측정을 더럽히지 않게)와 새 `--session-id` 를 준다.
2. **앞단 팔**은 판정만 새로 한다. 통과시킨 프롬프트는 기준선의 토큰 · 지연 · 답을 그대로 쓴다(아래 흐름이 같으므로 잡음이
   팔 사이 차이로 섞이지 않는다). 가로챈 프롬프트는 앞단의 답 · 토큰 · 지연을 쓴다.

| 팔 | 판정 |
|---|---|
| BASE | 늘 Claude |
| WALP | `walp.llmfront.SmallTalk().act` 가 잡담이라 하면 그 답(토큰 0), 아니면 Claude |
| MBA-0 | mba-front on, 관문 기본값(사전 1:1 -> p 0.5 ≤ θ 0.8): 캐시만. 컴파일 안 함 |
| MBA-1 | mba-front on, 관문 열림(사전 9:1 -- 토큰 차이 실측과 같은 설정): 캐시 -> **진짜** 작은 머리 컴파일 -> QUERY 실행 |
| STACK | WALP 가 먼저, 아니면 MBA-1 |

MBA 캐시는 훅과 같은 규칙으로 채운다: Claude 가 답한 턴이 저장소를 안 바꿨으면 (정준 질문 | 그 전 상태) -> 그 답.

## 사소한 설명 -- 재서 죽일 것
1. 이 묶음의 부류 비율(잡담 7 · 저장소 질문 6 · 반복 6)이 결과를 정한다 -- **부류별로 따로** 적는다. 실제 사용의 비율이 아니다
2. 통과 몫을 기준선에서 빌려 왔다 -- 앞단이 Claude 의 답을 바꾸지 않으므로 같은 흐름이다. 가로챈 몫만 새로 잰다
3. 한 번만 돌린다(n=1) -- 토큰 차이는 가로챈 프롬프트의 기준선 토큰과 같다. 기준선 호출의 런 간 범위는 V1 · V2 에서 ±1% 안이었다

## 무효화
- 기준선 호출 가운데 오류(is_error)가 있으면 그 프롬프트를 모든 팔에서 뺀다
- 판정 조건이 기준선 답에서도 틀리면(Claude 도 못 맞힘) 그 프롬프트의 "맞음" 을 주장하지 않는다

## 커밋 전에 본 것 (숨기지 않는다)

8(섞임) · 11 · 12(저장소 질문)를 잡담(greet · help)으로 가로채는 것을 **이미 봤다.** 프롬프트 목록은 그 뒤에 **바꾸지 않았다.**
